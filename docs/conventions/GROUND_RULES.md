# 팀 협업 및 의사소통 규칙

> 시간과 도구가 합의되지 않은 항목은 빈칸으로 둔다. 아래 운영 방식은 팀 논의용 제안이다.

## 회의 및 소통

- 정기 회의: 요일/시간/방식 TBD. 불참 시 가능한 한 사전 공유하고 결정 내용을 확인한다.
- 코어타임: TBD. 확정 전 특정 시간을 의무 시간으로 간주하지 않는다.
- 데일리 스크럼: 채널/주기 TBD. 진행한 경우 어제 한 일, 오늘 할 일, 막힌 점을 간단히 공유한다.
- 기본 소통 채널: Discord 등 TBD. 개발 결정은 채팅만으로 끝내지 않고 Issue/PR/결정 로그에 기록한다.
- 긴급 차단/일정 지연은 발견 즉시 영향, 이유, 필요한 도움/결정을 공유한다.

## 이슈와 리뷰

- 작업을 시작할 때 Issue와 완료 조건을 확인하고 담당/상태를 갱신한다.
- 리뷰 요청은 팀이 합의한 시간 안에 응답한다(목표 응답 시간 TBD). 즉시 응답을 보장할 수 없으면 예상 검토 시각을 알린다.
- 일정 지연을 숨기지 않고 조기 공유하며, 범위 조정은 팀과 합의해 기록한다.
- 부재 전 진행 상태, 브랜치/PR, 남은 작업, 막힌 점을 Issue에 기록한다. 인수자는 확인 질문과 수락 여부를 남긴다.

## 의사결정과 존중

- 제품 범위/우선순위는 팀 합의, 담당 영역 구현 세부는 담당자 제안과 동료 검토를 따른다.
- 의견 충돌 시 사용자 요구/제약/근거를 먼저 확인하고 대안을 비교한다. 합의가 안 되면 선택지·영향·결정자를 기록하고 멘토에게 질문한다.
- 결정에는 날짜, 참여자, 결론, 이유, 재검토 조건을 남긴다. 미결정은 TBD로 유지한다.
- 사람보다 코드와 요구사항을 논의하고, 질문/리뷰에 비난·조롱을 사용하지 않는다. 실수는 함께 해결하고 지식 격차를 존중한다.
