# 페이지 UI 및 동작 명세

> 기준: [CineFund Figma 시안](https://www.figma.com/file/bYyl4ZsROpGqfC7nvNWyTj?node-id=2:2&locale=ko-kr&type=design). Figma에서 확인되는 화면 요소와 실제 API/서버 동작의 결정 상태를 구분한다. 시안에 회원가입 화면은 없지만 상세 화면에는 **익명 펀딩 참여 입력 UI**가 있다. 회원가입이 없다는 이유만으로 펀딩 UI를 삭제하거나, 반대로 시안만으로 API 계약이 확정되었다고 보지 않는다.

> 라우팅 기준을 구분한다: 이전에 확인한 GitHub `main`의 `client/App.jsx`에는 `/`, `/detail`, `/compare`, `/compare-result`, `/ranking`이 등록되어 있다. 기존 기획/Figma 경로(`/`, `/{id}`, `/comparison`, `/results`, `/ranking`)와 다른 경로는 아래에서 목표와 현재 구현을 함께 기록한다. 화면 파일은 존재하지만 현재 placeholder라 동작 완료 상태가 아니다.

## 공통 UI

- 데스크톱·태블릿·모바일 화면 프레임이 준비되어 있다. 실제 브레이크포인트와 세부 반응형 동작은 구현 전 Figma에서 확인한다.
- 공통 헤더에는 로고, 영화 탐색/랭킹/비교 내비게이션, 영화 검색 입력이 보인다. 검색 API와 검색 대상 범위는 TBD다.
- 디자인은 밝은 배경과 카드형 영화 정보, 포스터, 청록색 계열 주요 액션/진행 표시를 사용한다. 정확한 색상 토큰·타이포그래피·간격은 디자인 시스템 기준을 확인한다.
- 로그인·회원가입·계정 생성 화면은 시안에 없다. 서비스는 비로그인 흐름으로 설계하며 사용자 상태를 쿠키/localStorage에 저장하지 않는다.
- 펀딩은 실제 결제가 아닌 모의 기능이다. 결제 수단 정보는 수집하지 않는다.
- 영화 제목·원제·한국 관람등급·개봉일·장르·설명·감독·슬로건·제작비·포스터는 **현재 JSON 및 Prisma 스키마의 저장 대상**이다. 페이지 데이터는 **향후 구현할 Express 영화 API**를 통해 PostgreSQL에서 조회해야 하며, 현재는 Express `/health`만 있다. 페이지마다 TMDB에 요청하지 않는다.
- 로딩·빈 결과·오류·재시도 화면은 시안에서 모두 확정되지 않았다. 구현 시 상태 설계와 문구를 보완한다.

## 페이지별 명세

| 목표 경로 (기획/Figma) | 현재 `main` 경로 | 목적 및 시안 구성 | 사용자 동작 및 데이터 | 상태 및 이동 |
|---|---|---|---|
| `/` | `/` | 영화 탐색. 펀딩 랭킹 Top 3 레일과 전체 영화 카드 목록, 공통 검색 헤더가 보인다. | 영화 카드 → 상세 목표 경로. 지정 100편, 기본 랜덤, 무한 스크롤과 누적 후원액 오름·내림 정렬을 제안한다. 달성률 정렬은 보류한다. 현재 `HomePage.jsx`는 placeholder다. 로딩/빈/오류·다음 페이지 동작은 구현 전. |
| `/{id}` | `/detail` (현재 동적 ID 없음) | 포스터·제목·메타 정보와 누적 펀딩, 코멘트, 펀딩 참여 영역. 시안의 진행 표시/목표액은 기준 미확정으로 구현 보류. 펀딩 취소와 코멘트 수정/비밀번호 확인 팝업 시안. | 익명 참여 입력은 닉네임·금액·코멘트·비밀번호·동의 항목으로 보인다. UI 및 API의 구체 계약은 별도 합의. 현재 `DetailPage.jsx`는 placeholder이며 라우트에 영화 ID 전달 방식이 없다. |
| `/comparison` | `/compare` | 영화 비교 선택. 검색 결과 패널, 선택 개수 `n/5`, 제거/추가와 비교 CTA. | 2~5개 선택 후 비교 결과 목표 경로로 이동. 검색 UI의 실제 기능/API는 TBD. 선택 상태는 메모리/URL 전달을 검토하며 브라우저 저장소로 보존하지 않는다. 현재 `ComparePage.jsx`는 placeholder다. |
| `/results` | `/compare-result` | 선택 영화를 비교표/카드로 비교. 시안에 설명·감독·펀딩액과 진행 표시 후보, 재선택/공유 액션과 AI 비교 요약 팝업이 있다. | 비교 항목·공유·AI 기능/서비스/비용은 미정. 달성률 기반 비교는 구현 보류. 선택 상태가 없으면 비교 선택으로 안내하는 흐름을 설계한다. 현재 `CompareResultPage.jsx`는 placeholder다. |
| `/ranking` | `/ranking` | 누적 후원액 기준 펀딩 순위. 시안의 10개 항목과 정렬 UI. | 금액 오름·내림차순을 우선 제안하며, 달성률 정렬은 목표 기준 확정 전 보류한다. 페이지 추가 로딩은 시안/기획대로 확인한다. 현재 `RankingPage.jsx`는 placeholder다. |

## 시안에서 확인된 내용과 미확정 내용

| 구분 | 항목 |
|---|---|
| 시안에서 확인 | 다섯 페이지 흐름, 검색 입력 UI, 펀딩 참여 입력 UI, 펀딩 취소 팝업, 코멘트 수정/비밀번호 팝업, 2~5개 비교 선택, 비교 결과, 랭킹, AI 요약 팝업, 데스크톱·태블릿·모바일 프레임 |
| 기존 기획에서 유지 | 영화 100편, 기본 랜덤 목록, 무한 스크롤, 펀딩액 정렬, 2~5개 비교, 닉네임 최대 8글자, 코멘트 최대 100글자, 최신 코멘트 10개 단위 |
| 팀/API 합의 필요 | 익명 펀딩 생성 endpoint와 서버 처리, 금액/통화 표시 정책, 달성률을 다시 도입할 경우 목표 기준 정의, 펀딩 취소가 실제 취소인지 팝업 닫기인지, 동의 문구 의미, 댓글 수정 권한/횟수, 검색 범위/API, AI 요약 MVP 여부, 비교 항목, 페이지 번호와 cursor 방식 |

## 이동 흐름

```mermaid
flowchart LR
  Home[영화 탐색 /] --> Detail[영화 상세 /id]
  Home --> Ranking[펀딩 랭킹 /ranking]
  Home --> Compare[비교 선택 /comparison]
  Compare --> Results[비교 결과 /results]
  Results --> Compare
  Ranking --> Detail
  Detail --> Compare
```

현재 React Router 경로는 저장소에 존재하지만 기획 경로와 일부 다르다. `/detail`에 영화 식별자를 path parameter 또는 다른 방식으로 전달할지, `/compare`와 `/compare-result`를 기획 경로로 바꿀지 팀/API 담당자와 결정하고 [API 명세](API_SPEC.md)와 함께 갱신한다. 디자인 화면이 코드 동작을 의미하지는 않는다.

화면은 **앞으로 구현할** CineFund 내부 서버 API를 통해 PostgreSQL 데이터를 받아야 한다. 2026-10-19 백엔드의 Express에는 `/health`만 있으므로 **화면 데이터 API는 아직 연결할 수 없다**. TMDB는 `movies:select` 초기 선정에서만 호출하고 `db:seed`는 고정 JSON을 읽는다. 제작비 원본은 USD, 후원액·누적액은 KRW다. 원화 제작비를 참고 표시할 경우 USD 원본에 고정 환율 1,400을 곱할 수 있으나 이는 별도 목표액이나 달성률 계산을 뜻하지 않는다.
