# 테스트 계획

> 현재 **BE 단위 테스트 도구는 Node.js 내장 `node:test`** (`pnpm test`)이며 `pnpm test:db`는 PostgreSQL 18과 영화 100편 시드를 확인한다. 아래 기능별 TC는 계획/기대 결과이고 실행 완료를 뜻하지 않는다.
> Figma에는 가입/로그인 화면 없이 모의 펀딩 참여 및 비밀번호 코멘트 수정 UI가 있다. 실제 결제는 범위에 없다. TC-06~TC-12의 서버 검증은 API 계약과 DB 구현이 준비된 뒤 실행한다. 그 전에 UI 상태/입력 표시 테스트는 진행할 수 있다. P0/P1은 검증 우선순위 제안이다.
> FE의 Vite/React scaffold와 ESLint 명령은 과거 GitHub `main` 확인 기준이다. **이 ZIP의 BE에는 Express `GET /health`, 영화 데이터 검증용 단위 테스트 7개, DB 검증 스크립트가 있다.** 팀별 환경에서 DB/서비스 통합 테스트 실행 완료를 주장하지 않는다.

## 현재 실행 방법 (BE)

```bash
pnpm test            # Node 내장 node:test: 영화 ID·등급·감독·제작비 검증 (DB 불필요)
pnpm db:up           # Docker PostgreSQL 18
pnpm db:migrate      # DB 테이블 적용
pnpm db:generate     # Prisma Client 생성
pnpm db:seed         # data/movieDetails.json 100편 저장
pnpm test:db         # 실제 PostgreSQL 버전·영화 100편·필드 비교
pnpm dev             # 서버 실행 후 http://localhost:3000/health 별도 확인
```

`pnpm test` 성공만으로 PostgreSQL 접속을 확인했다고 기록하지 않는다. `pnpm test:db`는 실행 가능한 DB와 시드가 필요하며 후원 API 트랜잭션 테스트를 대신하지 않는다. **TC-01~TC-20의 미구현 서비스 기능은 통과 처리하지 않는다.**

## 실행 시 기록할 항목

각 시나리오에 실행 환경, 테스트 데이터, 결과(Pass/Fail/미실행), 재현 절차, Issue 링크를 기록한다. P0 실패는 배포 차단으로 제안한다. 자동화 범위와 실제 통합/수동 테스트 비율은 팀 합의 후 정한다.
