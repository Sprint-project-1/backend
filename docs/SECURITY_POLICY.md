# 보안 정책

> 2026-10-19 백엔드에는 Express `/health`, Prisma/DB 연결, JSON 영화 검증, TMDB 선정 요청 코드가 존재한다. 하지만 **영화·펀딩 서비스 API는 미구현**이므로 아래 서버 인증/요청 검증/오류 처리·rate limit 요구를 이미 적용했다고 주장하지 않는다. 과거 FE `main` scaffold와 BE ZIP 준비 상태는 별개다.

> 로그인·회원가입·실제 결제는 범위에 없다. 서비스 목표는 비로그인 모의 펀딩이다. Figma에는 참여/코멘트 수정 UI가 있으며 구체 API·검증 방식은 합의 중이다. 아래 관련 보호 조치는 해당 서버 API를 구현할 때 적용하며 완전한 보안을 보장하지 않는다.

## 모든 기능에 적용할 최소 조치

- API 입력은 서버에서 검증한다. FE 검증은 사용성 보조이며 보안 경계로 간주하지 않는다.
- Prisma의 안전한 파라미터 바인딩을 사용하고 사용자 입력을 SQL 문자열에 직접 결합하지 않는다. Raw query가 필요하면 바인딩 매개변수를 사용한다.
- React는 사용자 제공 텍스트를 기본 escaping으로 출력한다. `dangerouslySetInnerHTML`은 사용하지 않으며 필요 시 별도 sanitization을 검토한다.
- `.env.example`은 변수 예시이고 실제 `.env`와 TMDB API 키, `DATABASE_URL` 등 비밀은 커밋하지 않는다(`.gitignore` 확인). **일반 `pnpm db:seed`에는 TMDB 키가 필요 없고 `pnpm movies:select`에서만 사용**한다. 프런트엔드 번들에 넣지 않으며 노출되면 키를 회전한다.
- 오류 응답은 일반화된 메시지와 코드만 반환한다. stack, SQL, 내부 호스트, 비밀 값은 노출하지 않는다.
- 서비스 API(아직 미구현)에서는 페이지 크기 상한 및 요청 횟수 제한을 적용할지 검토한다. TMDB **영화 선정 요청**의 `src/movies/tmdb.js`에는 timeout/재시도 코드가 있으나 장애 재현 검증은 별도 필요하다.

## 현재 구현과 미구현 경계

| 상태 | 내용 |
|---|---|
| 구현 | 로컬 `.env.example`·`.gitignore`, TMDB 재선정 키 분리, JSON 100편/제작비 조건 검증, Express BigInt JSON 문자열 직렬화, DB 접속 코드 |
| 아직 미구현 | 펀딩 등록 시 비밀번호 해시·검증, 요청 유효성 검사, 코멘트 수정 권한, 통일된 오류 JSON, 요청 제한, Funding 원장/누적액 트랜잭션 |
| 미확정 | 요청 금액 상하한/동의 처리, 운영 도메인/CORS (후원액은 KRW이며 목표 금액 기준은 현재 없음) |

## 모의 펀딩/코멘트 API 구현 시 추가 조치

- 닉네임 최대 8자, 코멘트 최대 100자, 양의 정수 금액 등 합의된 입력 제약을 서버에서 재검증한다. 문자 기준·금액 범위는 제품 합의가 선행되어야 한다.
- 비밀번호 기반 코멘트 수정 기능을 구현할 때 검증된 단방향 해시(예: Argon2id 또는 bcrypt 후보)만 저장한다. 평문/복호화 가능한 저장, 응답·로그 기록을 금지한다.
- 수정 비밀번호 검증과 펀딩 등록 endpoint에 rate limit을 적용할지 공개 전 결정한다. 비밀번호 오류는 기록 존재 여부를 불필요하게 노출하지 않는 응답을 사용한다.
- 금액 반영은 서버에서만 수행한다. Funding 원장과 합계 갱신은 원자적 DB 처리로 정합성을 유지한다.
- UI에서 가상 금액임을 명확히 알리고 결제정보·카드정보를 수집하지 않는다.

## 외부 API 및 익명 기능의 한계

TMDB의 사용 조건, attribution, 이미지 사용/캐시 정책, API 키 제한과 호출량은 영화 `movies:select` 재선정 전에 확인한다. 초기 적재 실패에 대비해 재시도와 안전한 재실행을 검토한다. 사용자 화면은 저장된 메타데이터를 기준으로 제공하므로 런타임 TMDB 장애에 의존하지 않는다.

로그인 없이 코멘트를 수정하면 작성자 확인, ID 추측, 반복 대입 위험이 남는다. 구현 시 난수 식별자, 적절한 해시 비용, 요청 제한, 수정 범위 제한과 비밀번호 분실 시 복구 불가 안내를 검토한다. 모의 펀딩은 사용자별 중복 방지와 기록 신뢰성을 보장하지 않으며, 운영 공개 범위와 악용 대응은 팀 합의가 필요하다.
